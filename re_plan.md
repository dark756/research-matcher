# re_plan.md: three switchable versions of the paper store

Status: **plan only, written 2026-11-09. Nothing in this file has been built yet.** It extends [plan.md](plan.md), which remains the design reference for the pipeline (M0–M9, all complete).

## 1. Goal

Run the project in three versions and switch between them with one CLI command:

| Version | Universities | How it is made |
|---|---|---|
| `current` | The existing 17 | The working state as of 2026-11-09, unchanged |
| `new` | Only the revised list (§6, to be supplied) | Cut down from `master` |
| `master` | Union of the existing 17 and the revised list | `current` plus the universities it lacks |

Hard requirement: the old snapshot and all original data stay safe. Building or using `new` and `master` must not be able to change them, and `current` must behave exactly as it does today.

## 2. What must stay safe

| Item | Where | Size | Why it matters |
|---|---|---|---|
| Snapshot of the 17-university build | `data/snapshots/v1-17unis/` | 1.96 GB | Saved 2026-11-09. SQLite `quick_check` passes |
| Database from the original (pre-rebuild) run | `data/papers.db.bak-20261106-225913` | 0.92 GB | The only copy of the first extraction run (37,279 works, 2,882 extractions) |
| Live working state | `data/papers.db`, `data/embeddings/`, `data/vectors/` | 1.9 GB | Becomes the `current` version |
| Hand-made labels and eval questions | `data/gold/` | 335 KB | Cannot be regenerated by a pipeline run |
| Downloaded CSRankings file | `data/cache/` | 3.9 MB | Reused by all versions |
| API keys | `.env.local` | small | Never copied into a snapshot or a repo |
| **Source code** | `src/`, `tests/`, `config/`, `pyproject.toml` | small | **Currently unprotected.** The project is not a git repository, and snapshots do not include code |

Until R1 is finished, these existing commands must not be used because each can damage the protected items:

- `snapshot use v1-17unis` moves the snapshot into the live position, so normal use then edits the only copy.
- `snapshot save v1-17unis --force` and `snapshot delete v1-17unis --yes` remove it.
- `run-all --fresh` renames the live DB and deletes the live embeddings and vectors.

## 3. Findings in the existing code that shape this plan

| # | Finding | Consequence if ignored | Fix |
|---|---|---|---|
| 1 | `snapshot use` moves folders, so a snapshot stops existing as a separate copy while it is active | The "safe" copy gets modified by normal use | Versions live side by side and are never moved (§4) |
| 2 | `embed_all` caches embeddings by chunk number, and papers are sorted by `work_id` | Adding papers shifts them between chunks. Old chunks are reused for the wrong papers, **silently corrupting search** | Cache embeddings by `work_id` (R3). This also means only new papers are embedded |
| 3 | `store_work` skips papers already stored, unless run with `refresh` | A paper by ETH and MIT authors stays tagged ETH only, undercounting every added university | Offline "retag" step built from `authorships.inst_ids_json`, which already holds every author's full institution lineage (211,165 rows). No API calls |
| 4 | `run_harvest` always queries the whole university list | `master` would re-download all 17 universities, and those papers would drift from `current` | `harvest --only-unis` for just the added universities |
| 5 | `paper_payloads` and `run_professors` look up every `work_universities` row in the YAML list | A paper tagged with a university that is not in the list raises an error. Simply editing the YAML to make `new` will crash | `new` must delete those rows and any paper left with no target university (R4) |
| 6 | Papers with authors at several target universities are common (3,281 works) | Cutting down to `new` must drop only the removed university's tag, not the paper | Same subset step as #5 |
| 7 | `rag_eval.json` names specific universities and paper ids (ETH, CMU, NUS, Oxford, Gustavo Alonso) | Questions fail in `new` if those universities are dropped, which looks like a retrieval bug | Mark such questions not applicable per version (R5) |

There are no functional hardcoded "17" checks. The number appears only in comments and in the expected-count text of `harvest-check`. Adding a university needs a YAML entry, not a code change to the count.

## 4. Target design

### Layout

Each version is a complete, independent folder. Nothing moves when you switch.

```
data/
  snapshots/
    v1-17unis/      sealed archive, never used directly
    current/        papers.db  embeddings/  vectors/  weights.json  calibration.json
    new/            config/universities.yaml  config/settings.yaml  BENCHMARK_CANDIDATES.md
    master/         manifest.json (status, counts, fingerprint)
  .active           one line: current | new | master
  papers.db.bak-20261106-225913    sealed
  gold/  cache/  notes/            shared by all versions
```

`Settings.path()` resolves the database, embeddings and vectors inside the active version. Gold labels, the CSRankings cache and notes resolve to the shared location. `load_universities()` and `load_settings()` read the version's own config files, because the thresholds and the university list belong to a version.

Why this rather than improving the current folder-swap: switching becomes writing one short file, so it cannot fail halfway, cannot lose data, and is not blocked by an open `chat`. A running `chat` simply stays on the version it started with.

### Commands

```
research-matcher snapshot list               # versions, status, papers, universities, size, which is active
research-matcher snapshot use master         # switch (current | new | master)
research-matcher --snapshot new ask "..."    # one command against another version, without switching
research-matcher snapshot verify current     # compare against the sealed fingerprint
research-matcher snapshot restore current    # rebuild current from the sealed archive
```

### Guards

- **Sealed items** (`v1-17unis`, the `.bak` file) are marked read-only on disk and have recorded SHA-256 hashes. Read-only stops writes and deletes but not renames, so the code also refuses every operation on them.
- **`current` is protected.** Commands that change data (`harvest`, `enrich`, `prefilter`, `extract`, `extract-post`, `index`, `match`, `match-calibrate`, `run-all`) refuse to run while it is active. `chat` and `ask` are allowed.
- **`run-all --fresh`** is refused on `current`.
- **`snapshot use`** refuses a version whose manifest does not say `ready`, so a half-built version cannot be selected.
- **`delete` and `save --force`** are removed for `current` and the sealed items.
- **Disk space** is checked before any copy.

## 5. Build order

Build `master` first and cut `new` out of it. `new` needs no second download and no second extraction run, because every paper with an author at a revised-list university is already in `master`. Extraction is by far the slowest stage (288.8 minutes last run), so it should be paid for once, and only for papers not already extracted.

- [ ] **R2 University list and dry run.** Add the §6 list. Query OpenAlex for paper counts per candidate (about 1 credit each).
  **Gate:** you approve the list and the projected size and time, using real counts.

- [ ] **R3 Build `master`.** Copy `current` to `master` (status `building`) and set its list to the union. Then:
  1. `init` to seed institutions and faculty.
  2. `harvest --only-unis`, then retag.
  3. `enrich`, then prefilter with embeddings keyed by `work_id`.
  4. `extract` (only new survivors), `extract-post`, `index`, `match`, `report`.

  Thresholds and weights stay as calibrated for `current`.
  **Gate:** every paper from `current` is present. A sample of 20 co-authored papers has correct tags. Vector and SQLite counts match. Each embedding row matches a recomputed sample. Filtered search p95 is under 300 ms. `verify current` still passes.

Delete `work_universities` rows, institutions and faculty for dropped universities, and delete papers left with no target university. Rerun dedupe (a canonical record may have been removed), subset the embeddings, then rerun prefilter, `extract` (only papers that became canonical), `index`, `match`, `report`.
  **Gate:** no paper lacks a revised-list university, no row references a dropped one, counts match, and `verify current` and a `master` fingerprint check both pass.

- [ ] **R5 Evaluate and compare.** Run `ask-eval` on all three, with questions naming absent universities marked not applicable, and save a comparison table of papers, universities, survivors, pairs, clusters, latency and eval results.
  **Gate:** each version meets the M7 thresholds on its applicable questions, or the shortfall is explained.

- [ ] **R6 Document.** Update `README.md` and add a pointer from `plan.md`.

## 8. Estimates

Measured from the last full run (36,569 canonical papers, 17 universities): harvest 16.3 min, enrich 1.9, prefilter 13.6, extract 288.8 (about 6 s per paper), extract-post 10.6, index 1.4, match 9.1, report 2.5. The survivor rate was 7.9%.

Average per added university: about 2,150 papers and 170 survivors, so roughly 17 minutes of extraction. **Large schools such as MIT or Stanford are likely to be higher, so R2 replaces these with real numbers.**

| Added universities | New papers | New survivors | `master` build | `new` build |
|---|---|---|---|---|
| 5 | ~11,000 | ~850 | ~2 h | ~30 min |
| 10 | ~21,500 | ~1,700 | ~3.5 h | ~30 min |
| 20 | ~43,000 | ~3,400 | ~6.5 h | ~45 min |

OpenAlex cost should be small against the 10,000 daily credits: the plan's budget for all 17 universities was 450–1,200. Disk: about 3 GB for `master` with 10 added universities, and less for `new`. About 300 GB is free.

## 9. Known limits

- **Different harvest dates.** Papers from the 17 universities are frozen at the 2026-11-05 harvest, and added universities are as of the build date. A university's count in `master` is not strictly comparable to a newly added one. Decision 2 covers this.
- **Calibration is carried over, not refit.** Weights, thresholds and gold pairs were fitted on the 17 universities. The strict-rubric shortfall recorded for M6 still applies, and more universities will not fix it by themselves.
- **Survivor target.** The prefilter's 2,000–5,000 target will be exceeded by a large `master`. That is only a warning, but the three subdomains may become unbalanced.
- **Cluster and topic IDs differ between versions.** Compare them by content, not by ID.
- **Topic labels, entities and claims are LLM output.** Rebuilt data can drift slightly (under 1% in the last full rebuild).
- **One physical disk.** All copies sit on the same drive, so a disk failure would lose everything (decision 4).

## 10. Decisions needed

1. **The revised university list** (§6). This blocks R2 onward.
2. **Harvest dates in `master`.** Recommended: harvest only the added universities, so `master` is a strict superset of `current`. The alternative re-queries all universities, which makes dates consistent but means `master` also contains newer papers for the 17.
3. **Version control.** Recommended: `git init` before any code change, so code can be matched to data versions. Needs your approval, and `.env.local` and `data/` must be excluded.
4. **Off-drive backup.** Recommended: copy the sealed items (about 2.9 GB) to an external drive or cloud storage.
